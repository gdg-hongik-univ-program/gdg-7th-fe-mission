## Refactoring

리팩터링은 프로그램이 하는 일(동작)은 그대로 두고, 코드 구조만 더 읽기 쉽고 고치기 쉽게 바꾸는 것이다. 기능이 추가되거나 결과가 달라지면 리팩터링이 아니다.

필요한 이유
- 기능을 계속 붙이다 보면 코드가 길어지고, 나중에 내가 쓴 코드도 읽기 어려워진다.
- 같은 코드가 여러 군데 있으면 하나를 고칠 때 나머지도 다 찾아서 고쳐야 한다.
- 변수 이름, 불필요한 주석, 너무 긴 함수 같은 걸 바로바로 정리해 두면 수정할 때 실수가 줄어든다.

한 번에 크게 갈아엎기보다는, 코드를 건드릴 때마다 조금씩 더 깔끔하게 만들어 두는 게 좋다. 

## Custom Hook

커스텀 훅은 useState, useEffect 같은 React 훅을 묶어서 직접 만든 훅이다. 여러 컴포넌트에서 반복되는 상태 관련 로직을 함수 하나로 빼서 재사용할 때 쓴다.

규칙
- 이름은 use로 시작해야 한다. (예: useProducts)
- 안에서 다른 훅을 호출할 수 있다.
- 컴포넌트 최상단에서 호출해야 한다. (조건문, 반복문 안에서 호출 X)

사용 목적
- 컴포넌트에서 데이터 불러오기 같은 로직을 분리해서 화면 코드만 남길 수 있다.
- 같은 로직을 여러 컴포넌트에서 재사용할 수 있다.
- 훅을 같이 써도 state 자체는 공유되지 않고, 호출한 컴포넌트마다 따로 생긴다.

## 일반 함수 vs Custom Hook

- 일반 함수는 값을 받아서 계산하고 결과를 돌려주는 역할만 한다. 안에서 useState 같은 훅을 쓸 수 없다.
- 커스텀 훅은 안에서 state를 가질 수 있고, 그 state가 바뀌면 훅을 쓰는 컴포넌트가 다시 렌더링된다.
- 그래서 상태 없이 계산만 하는 건 일반 함수(utils)로, 상태나 useEffect가 필요한 로직은 커스텀 훅으로 만드는 게 맞다.

## 쇼핑몰 코드에 적용할 수 있는 부분

지금 App.jsx에는 상품 목록을 불러오는 코드가 길게 들어가 있다.

const [products, setProducts] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState("");

useEffect(() => {
  // getProducts()로 상품을 불러오고 loading, error 처리
}, []);

App은 원래 라우팅이랑 전체 화면 배치를 담당하는 컴포넌트인데, 데이터 불러오는 로직까지 같이 있어서 길어졌다. 이 부분을 useProducts라는 커스텀 훅으로 분리하면 App에서는 아래 한 줄로 쓸 수 있다.

const { products, setProducts, loading, error } = useProducts();

이렇게 하면 App은 화면 구성만 남아서 읽기 쉬워지고, 상품을 불러오는 방식이 바뀌어도 훅 파일 하나만 고치면 된다.
