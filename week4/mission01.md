# Refactoring

## 의미
 **리팩토링(refactoring)**은 하는 일은 그대로 두고 코드의 구조만을 읽기 쉽게 그리고 고치기 쉽게 바꾸는 일이다.

- 버그 수정, 새 기능 추가는 리팩토링이 아니다.

## 필요성
- 컴포넌트 하나가 너무 많은 일을 할 경우 리팩토링 역할별로 나눠서 읽기 쉬워지게 할 수 있다.
- 코드를 처음보는 사람도 이해하기가 쉽게 만들어진다.
- 구조가 정리되면 기능 추가와 버그 수정이 빨라진다.

# Custom Hook

## 개념
**Custom Hook**은 `useState`, `useEffect` 같은 **React Hook**을 사용하는 로직을 함수로 묶어서 재사용 가능하게 하는 것
- 이름은 use로 시작해야한다. 
- 컴포넌트처럼 함수 안에서 다른 Hook을 호출 할 수 있다.
- JSX(화면)을 반환하지 않고, 상태 값과 함수를 반환한다.

## 사용 목적
1. 상태 로직 재사용
2. 컴포넌트를 깔끔하게 만들기 위해서
3. 관심사를 분리하여 테스트와 수정이 쉬워진다.

# 일반 함수와 Custom Hook의 차이점

| 구분 | 일반 함수 | Custom Hook |
| --- | --- | --- |
| 이름 규칙 | 자유 | use로 시작 |
| 내부에서 Hook 사용 | 불가 | 가능 |
| 호출할 수 있는 곳 | 어디서든 | 컴포넌트 최상단 또는 다른 Custom Hook 안에서만 |
| 조건문/반복문 안 호출 | 가능 | 불가 (Hook 규칙: 항상 같은 순서로 호출) |
| 값 기억 | 호출할 때마다 새로 계산하고 끝 | 리렌더링 사이에도 상태를 기억 상태가 바뀌면 화면이 다시 |
| 주로 하는 일 | 계산, 변환 (값 → 값) | 상태 + 부수효과(데이터 불러오기 등) 관리 |
