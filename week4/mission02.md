linting은 코드를 실행하기 전에 분석하여 잠재적인 오류, 잘못된 코드, 규칙 위반 등을 찾아내는 작업이다. formatting은 코드의 내용을 바꾸지는 않고 규칙에 맞춰 형식만 정리하는 작업이다.
eslint는 코드를 분석해서 문제가 될 수 있는 부분을 찾아주는 도구이다. prettier 코드의 형식을 자동으로 정리해 주는 도구이다. 위에서 설명한 linting을 해주는 것이 eslint이고 formatting을 해주는 것이 prettier이다. 가장 큰 차이는 eslint는 미사용 변수를 감지하고 규칙을 검사하지만 prettier은 미사용 변수를 감지하지 못하고 코드 형식을 자동으로 정리해준다.
autosave를 끈 뒤 npm run lint를 사용해 바꾼 것들
1. 사용하지 않는 불필요한 변수를 다 제거했다. 이 과정은 바로 들어가서 쓰지 않는 것들만 지우면 되서 어렵지 않았다.
2. 정의되지 않은 변수같은 경우는 대부분 import를 하지 않아 발생했기 떄문에 import만 해주면 해결이 되었다.
3. react hook 규칙 위반한 경우를 고치는 것이 번거로웠다. 한 페이지 안에 export funciton이 두개 있어서 앞에 export를 빼고 한꺼번에 마지막에 export를 해도 똑같이 컴포넌트의 상태를 안정적으로 유지하기 힘들기 때문에 결국 페이지를 따로 만들고 해당 페이지를 쓰는 페이지를 다 찾아 새로 import해주었다. 그랬더니 eslint에는 오류가 뜨지 않았지만 오히려 반대로 웹사이트에서 오류가 났다. 그래서 결국 다시 합쳐서 원점으로 돌아왔다. eslint를 무조건으로 따라서는 안된다는 생각이 들었다.
