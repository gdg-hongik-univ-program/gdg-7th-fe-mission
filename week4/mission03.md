# 상태 관리

## 개념
**상태 관리(State Management)**는 여러 컴포넌트가 함께 쓰는 데이터(state)를 어디에 두고, 어떻게 꺼내 쓰고 바꿀지 정하는 것이다.

## 필요성
- 앱이 커지면 같은 데이터를 여러 컴포넌트가 같이 써야 한다. (ex. 장바구니)
- 데이터가 어디서 바뀌는지 모르면 버그를 찾기 어렵다.
- 한 곳에서 관리하면 데이터 흐름이 잘 보이고 수정이 쉬워진다.

# Props Drilling

## 개념
**Props Drilling**은 데이터가 필요한 컴포넌트까지 가려고, 중간 컴포넌트들이 쓰지도 않는 props를 계속 아래로 넘겨 주는 것이다.

## 쇼핑몰 코드 예시
`cart`, `setCart`는 `App.jsx`에 있고, 실제로 쓰는 곳은 `Item.jsx`이다.
```
App (cart, setCart 만듦)
 → CategoryPage (안 쓰고 넘겨주기만 함)
   → Item (여기서 씀)
```
`Content`, `PricePage`, `SortPage`도 똑같이 넘겨주기만 한다.

## 문제점
- 중간 컴포넌트가 쓰지도 않는 props를 받아야 해서 코드가 지저분해진다.
- props 이름이 바뀌면 지나가는 모든 컴포넌트를 다 고쳐야 한다.
- 단계가 깊어질수록 데이터가 어디서 왔는지 찾기 어렵다.

# Context와 useContext

## Context
- 데이터를 props로 한 단계씩 넘기지 않고, 아래에 있는 컴포넌트 어디서든 바로 꺼내 쓸 수 있게 해 주는 React 기능이다.
- `createContext`로 만들고, `Provider`로 감싼 범위 안에서 쓸 수 있다.

## useContext
- Context에 담긴 값을 꺼내 쓰는 Hook이다.
- `const { cart, setCart } = useContext(CartContext);` 처럼 쓴다.

# 상태 관리 라이브러리

## Context가 있는데도 라이브러리를 쓰는 이유
- Context 값이 바뀌면 그 Context를 쓰는 컴포넌트가 전부 다시 그려진다. 앱이 커지면 느려질 수 있다.
- 상태가 많아지면 Provider를 여러 겹 감싸야 해서 코드가 복잡해진다.
- 라이브러리는 필요한 값만 골라 쓰고, 더 짧은 코드로 관리할 수 있다.

## Zustand

### 특징
- 사용법이 간단하고 코드가 짧다.
- Provider로 감쌀 필요가 없다.
- 컴포넌트가 필요한 값만 골라서 가져오기 때문에, 그 값이 바뀔 때만 다시 그려진다.

### 사용법
- `create`로 저장소(store)를 만들고, 상태와 상태를 바꾸는 함수를 같이 넣는다.
- 컴포넌트에서는 Hook처럼 불러서 필요한 것만 꺼내 쓴다.

## 장단점

### 장점
- 코드가 짧고 배우기 쉽다.
- Provider가 필요 없다.
- 필요한 값만 구독해서 불필요한 렌더링이 적다.

### 단점
- 따로 설치해야 한다. (`npm install zustand`)
- 정해진 규칙이 적어서, 팀에서 쓰는 방식을 따로 맞춰야 한다.
- 아주 큰 프로젝트에서는 Redux Toolkit보다 관리 도구(디버깅 등)가 적다.
