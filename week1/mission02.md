# 컴포넌트

컴포넌트는 재사용이 가능하고 독립된 작은 UI 조각이다. 레고 블록처럼 각각의 컴포넌트를 만들고 조합해서 하나의 화면을 만든다.

## 왜 컴포넌트로 나누어야 할까?

- 재사용: 같은 모양이 반복되는 UI를 컴포넌트 하나로 만들어 두면, Props로 데이터만 바꿔서 여러 곳에 쓸 수 있다. 예를 들어 쇼핑몰의 상품 카드는 컴포넌트 하나로 모든 상품을 표현할 수 있다.

- 유지보수: 수정할 부분이 있으면 해당 컴포넌트만 고치면 된다. 이번 과제에서 Navbar의 버튼을 바꾸려면 Navbar.jsx만 열면 되고, 다른 부분에 영향을 주지 않는다.

- 가독성: App.jsx가 Navbar, Content, Footer 세 줄로 끝나서 코드만 봐도 화면 구조를 바로 알 수 있다.

- 협업: 컴포넌트 단위로 작업을 나눌 수 있어서 여러 사람이 동시에 개발하기 쉽다.

## 어떤 기준으로 나누는 것이 좋을까?

- 역할 단위: 화면에서 각 영역이 하는 역할을 기준으로 나눈다. 이번 과제에서는 0주차에 시맨틱 태그로 분석했던 구조를 그대로 따라 상단 메뉴(Navbar), 본문(Content), 하단 버튼(Footer)으로 나누었다.

- 반복되는 UI: 여러 번 반복되는 부분은 따로 컴포넌트로 만든다. (예: 상품 카드, 버튼)

- 너무 잘게 나누지 않기: 의미 없이 지나치게 쪼개면 파일만 많아지고 오히려 구조를 파악하기 어려워진다. 재사용할 일이 있거나 역할이 분명할 때 나누는 것이 좋다.
