# 컴포넌트 학습
컴포넌트는 화면을 구성하는 재사용 가능한 UI 조각이다. 


React에서는 JSX를 반환하는 함수로 만든다.

## 왜 컴포넌트로 나누어야 할까?
- 재사용: 한번 만든 컴포넌트를 여러 곳에서 가져다 쓸 수 있다.
- 가독성: 파일이 역할별로 나뉘어 코드가 짧고 읽기 쉽다.
- 유지보수: 수정할 곳이 한 파일에 모여 있어서 고치기 쉽다.
- 협업: 팀원이 작업을 쪼개서 하기에 좋다.
- 독립성: 컴포넌트마다 자기 state와 동작을 가져서, 한 곳의 변경이 다른 곳에 영향을 덜 준다.

## 어떤 기준으로 나누는게 좋은가
1. 화면의 역할 및 영역별로 나누어야 한다. 
    - `Navbar`: 상단 메뉴
    - `Content`: 본문
    - `Footer`: 하단 영역
2. 반복되는 모양은 컴포넌트로 만든다. 

    같은 모양의 버튼이나 이미지 등이 반복되면 컴포넌트를 쓰면 재사용하기 편하다. 

3. 너무 많은 일을 하면 컴포넌트를 쪼개는데, 너무 잘게 쪼개지는 않는다. 

    가독성을 높이기 위함이다. 

# 헷갈렸던 내용
`<div>`같은 태그로 컴포넌트 리턴문 안을 묶어줘야 한다. 
컴포넌트는 하나의 태그만 반환하기 때문이다. 

`<a>`태그는 클릭했을 때 이동하는 그런 태그이다. 

`<button>`태그에서 `onClick={() => handleClick()`으로 미리 지정한 함수 `handleClick()`을 클릭을 함으로써 호출할 수 있다.

`body`의 css 스타일을 지정함으로써 기본적인 css스타일을 지정할 수 있다. 

검색 기능을 구현할 떄는 `<form>` 태그와 `<section>` 태그를 같이 쓰고, 현재 상태를 나타내는 값과 검색한 값을 나타내는 값을 `useState`를 써서 담을 수 있다. 

`cursor: pointer`로 버튼에 마우스를 대면 커서를 변하게 할 수 있다. 

`justify-content`와 `align-items`는 `flex`를 준 부모에서만 동작한다.

클릭에 대한 함수는 `onClick={f()}`가 아니라 `onClick={() => f()}`를 써야 한다.
