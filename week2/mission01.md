# Props와 State

Props는 부모 컴포넌트가 자식 컴포넌트에게 넘겨주는 값이다.
HTML 태그에 속성을 쓰는 것처럼 이름={값} 형태로 넘기고, 자식은 이를 객체 하나로 받는다. 보통은 구조 분해 할당으로 필요한 값만 꺼내서 쓴다.

function Item({ itemName, price }) {
return <p>{itemName} - {price}원</p>;
}

<Item itemName="원피스" price={500} />

Props를 쓰면 모양은 같고 내용만 다른 UI를 컴포넌트 하나로 재사용할 수 있다. 예를 들어 상품 카드를 하나만 만들어 두고, 상품 데이터 배열을 map으로 돌려서 카드 여러 개를 만들 수 있다.
Props는 읽기 전용이라 자식 컴포넌트에서 값을 바꾸면 안 된다. 데이터는 항상 부모에서 자식으로, 한 방향으로만 흐른다.

State는 컴포넌트가 스스로 기억하고 있는 값이다.
사용자의 행동에 따라 바뀌는 값, 예를 들어 구매 수량이나 검색어, 장바구니 같은 것들을 State로 관리한다. State는 set 함수로만 바꿀 수 있고, 값이 바뀌면 컴포넌트가 다시 렌더링되면서 화면에 바로 반영된다.

정리하면 Props는 밖에서 받는 값이라 바꿀 수 없고, State는 컴포넌트 안에서 관리하는 값이라 바꿀 수 있다. 함수로 비유하면 Props는 매개변수, State는 함수 안에서 기억하는 변수에 가깝다고 이해했다.

# React Hooks

Hook은 함수형 컴포넌트에서 State 관리 같은 기능을 쓸 수 있게 해주는 함수이다. 이름이 모두 use로 시작하고, 컴포넌트 함수의 최상단에서만 호출해야 한다. if문이나 반복문 안에서는 쓸 수 없다.

### useState

컴포넌트가 기억해야 하는 값을 만들 때 쓴다.

const [count, setCount] = useState(1);

useState는 현재 값과 그 값을 바꾸는 함수를 배열로 돌려주기 때문에 배열 구조 분해 할당으로 받는다. setCount로 값을 바꾸면 React가 컴포넌트 함수를 다시 실행해서 바뀐 값으로 화면을 그린다.
그냥 let 변수를 쓰면 안 되는 이유는, 컴포넌트가 다시 렌더링될 때마다 함수가 처음부터 다시 실행되면서 값이 초기화되고, React도 값이 바뀐 걸 알지 못해서 화면이 바뀌지 않기 때문이다.

### useEffect

화면이 렌더링된 이후에 실행할 작업을 넣을 때 쓴다. 서버에서 데이터 불러오기, 이벤트 리스너 등록처럼 화면을 그리는 것 외의 작업(side effect)을 처리한다.

useEffect(() => {
console.log(수량이 ${count}개로 바뀌었다);
}, [count]);

두 번째 인자인 의존성 배열에 따라 실행 시점이 달라진다.
빈 배열 [] 을 넣으면 처음 렌더링될 때 한 번만 실행된다.
[count]처럼 값을 넣으면 처음 한 번, 그리고 그 값이 바뀔 때마다 실행된다.
배열을 아예 안 넣으면 렌더링될 때마다 매번 실행된다.

또 useEffect 안에서 함수를 return하면 컴포넌트가 사라질 때 실행되는데, 타이머를 끄거나 이벤트를 해제하는 정리 작업에 쓴다.

### useNavigate

React Router에서 제공하는 Hook으로, 코드에서 다른 페이지로 이동할 때 쓴다.

const navigate = useNavigate();

<button onClick={() => navigate(“/category”)}>카테고리 필터링</button>

navigate(“/경로”)를 호출하면 주소가 바뀌면서 그 경로에 연결된 페이지 컴포넌트가 화면에 나타난다. Link는 클릭하면 이동하는 링크를 만드는 거라면, useNavigate는 버튼 클릭 후처럼 원하는 시점에 코드로 이동시킬 수 있다는 차이가 있다.
