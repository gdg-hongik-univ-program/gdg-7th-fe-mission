# HTTP와 API 통신 알아보기

## HTTP
HTTP는 HTML 문서와 같은 리소스들을 가져올 수 있도록 해주는 프로토콜이다. 
- (프로토콜: 컴퓨터 내에서, 또는 컴퓨터 사이에서 데이터의 교환 방식을 정의하는 규칙 체계)  
또 웹에서 이루어지는 모든 데이터 교환의 기초이며, 클라이언트-서버 프로토콜이다. 
- 클라이언트-서버 프로토콜: 수신자 측에 의해 요청이 초기화되는 프로토콜
    - 클라이언트와 서버들은 개별적인 메시지 교환에 의해 통신한다. 
    - 요청: 브라우저인 클라이언트에 의해 전송되는 메시지
    - 응답: 그에 대해 서버에서 응답으로 전송되는 메시지

HTTP는 TCP 혹은 암호화된 TCP연결인 TLS를 통해 전송된다. 

### HTTP 기반 시스템의 구성 요소
요청은 하나의 개체, 사용자 에이전트(혹은 프록시)에 의해 전송된다.  
각각의 개별적 요청들은 서버로 보내지고, 서버는 요청을 처리하고 응답을 제공한다.  

#### 클라이언트(사용자 에이전트)
사용자 에이전트는 사용자를 대신하며 동작하는 모든 도구이다.  
클라이언트는 요청을 보내는 쪽인데, 보통 브라우저이다.  
요청은 항상 클라이언트가 먼저 시작한다. 

#### 웹 서버
통신 채널의 반대편에는 클라이언트에 의한 요청에 대한 문서를 제공하는 서버가 존재한다.  
요청을 받아서 응답을 돌려주는 쪽이다. 

#### 프록시
웹 브라우저와 서버 사이에는 수많은 컴퓨터와 머신이 HTTP 메시지를 이어 받고 전달한다. 
이러한 컴퓨터/머신 중에서도 애플리케이션 계층에서 동작하는 것들을 프록시라고 한다. 

### HTTP의 특징
- 간단하다. 
    - 메시지를 사람이 읽을 수 있다. 
- 확장 가능하다. 
    - 헤더에 정보를 추가해서 새 기능을 붙일 수 있다. 
- 상태가 없다. 
    - 서버는 이전 요청을 기억하지 않는다.
    - 요청 하나하나가 독립적이다. 
- 그래도 세션은 있다. 
    - 쿠키를 쓰면 로그인 상태나 장바구니처럼 이어지는 정보를 유지할 수도 있다. 

### HTTP 메시지

#### 요청
```js
GET / HTTP/1.1
Host: developer.mozilla.org
Accept-Language: fr
```
- 메서드: `get`처럼 무엇을 할지 동작을 정의  
- 경로: `/`처럼 어떤 자원에 대해서인지 경로  
- 버전: `HTTP/1.1`같은 거
- 헤더: `Host: ...`: 추가 정보를 나타냄
- 본문: `POST`와 같은 몇 가지 메서드를 위해, 전송된 리소스를 포함하는 응답의 본문과 유사한 본문

#### 응답
```js
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 29769

<!DOCTYPE html...
```
- 버전
- 상태코드: `200` 같은거
- 상태 메시지: `OK` 등 상태 코드를 짧게 설명한 말
- 헤더: `Content-type: ...`
- 본문: HTML, JSON 등 실제로 돌려주는 데이터

### HTTP 메서드
- `GET`: 조회
- `POST`: 등록
- `PUT`: 전체 수정
- `PATCH`: 부분 수정
- `DELETE`: 삭제

`GET`은 데이터를 가져오기만 하고 서버 내용은 안 바꾼다.  
`POST`는 서버의 상태를 바꾼다. 

### 상태 코드
- 1XX: 처리 중
- 2XX: 성공
    - `200 OK`: 성공
    - `201 Created`: 새로 만들어짐
    - `204 No Content`: 성공했지만 돌려줄 내용 없음
- 3XX: 다른 곳으로 이동 필요
- 4XX: 클라이언트 잘못
    - `400`: 요청이 잘못됨
    - `401`: 로그인 필요
    - `403`: 권한 없음
    - `404`: 찾을 수 없음
- 5XX: 서버 잘못
    - `500`: 서버 내부 오류

앞자리가 4이면 내가 보낸 요청을, 5이면 서버 쪽을 확인하면 된다. 

### API 통신
API는 서버가 "이 주소로, 이 메서드로 요청하면 이런 데이터를 줄게"라고 정해 둔 창구이다. like 식당의 메뉴판

|하고 싶은 일|메서드 + 주소(예시)|
|---|---|
|상품 목록 조회|`GET /items`|
|상품 하나 조회|`GET /items/3`|
|상품 등록|`POST /items`|
|상품 수정|`PATCH /items/3`|
|상품 삭제|`DELETE /items/3`|

같은 주소(`/items`)라도 메서드에 따라 하는 일이 달라진다.  
브라우저에서는 `fetch`로 요청을 보낸다. 

```js
// 조회 (GET)
const response = await fetch("/items");
const items = await response.json();

// 등록 (POST)
await fetch("/items", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ itemName: "원피스", price: 500 }),
});
```
서버 응답은 시간이 걸리니까 비동기로 기다린다.  
데이터는 보통 JSON 형식으로 주고 받는다. 

# 동기·비동기 처리 알아보기

## 동기(synchronous)
직렬적으로 테스크를 수행하는 방식이다.  
요청을 보낸 후 응답을 받아야만 다음 동작이 이루어진다. 
어떤 테스크를 처리할 동안 나머지 테스크는 대기하므로 효율이 떨어진다. 

## 비동기(asynchronous)
병렬적으로 테스크를 수행하는 방식이다.  
요청을 보낸 후 응답의 수락 여부와는 상관없이 다음 테스크가 동작하는 방식이다.  
a 테스크가 실행되는 동안 b  테스크를 할 수 있으므로 자원을 효율적으로 사용할 수 있다.  
비동기 요청 시 음답 후 처리할 '콜백 함수'를 함꼐 알려준다.  
해당 테스크가 완료되면 '콜백 함수'가 호출된다. 

하지만 콜백 패턴을 사요하면 처리 순서를 보장하기 위해 여러 콜백 함수가 중첩되어 복잡도가 높아지는 **콜백 헬**이 발생하는 단점이있다.  

## Promise
비동기 작업의 "나중에 올 결과"를 나타내는 객체이다.  
"지금은 결과가 없지만, 끝나면 성공인지 실패인지 알려 줄게"라는 약속이다. 
- 진동벨

Promise가 가지는 상태
|상태|뜻|
|----|----|
|pending|비동기 처리가 아직 수행되지 않은 상태|
|fulfilled|비동기 처리가 수행된 상태(성공)|
|rejeted|비동기 처리가 수행된 상태(실패)|
|settled|비동기 처리가 수행된 상태(성공 또는 실패)|

### Promise 호출 과정
1. 비동기 함수 내에서 Promise 객체를 생성하고 그 내부에서 비동기 처리를 구현한다. 성공하면 resolve 함수를 호출한다. 
2. 이때 resolve 메소드의 인자로 비동기 처리 결과를 전달하는데, 이 처리 결과는 Promise 객체의 후속 처리 메소드로 전달된다. 
3. 만약 비동기 처리에 실패하면 reject 메서드를 호출하고 그 인자로 에러 메시지를 전달한다. 

후속 처리 메서드
- `.then()`: 성공했을 때 할 일
- `.catch()`: 실패했을 때 할 일
- `.finally()`: 결과와 상관없이 마지막에 실행됨

then과 catch는  Promise를 반환한다.  
### Promise 체이닝
then은 새 Promise를 돌려줘서 계속 이어 붙일 수 있고 앞 then의 `return`값이 다음 then으로 넘어간다. 
```js
// 포스트 id가 1인 포스트를 검색하고 프로미스를 반환한다.
promiseAjax('GET', `${url}/1`)
  // 포스트 id가 1인 포스트를 작성한 사용자의 아이디로 작성된 모든 포스트를 검색하고 프로미스를 반환한다.
  .then(res => promiseAjax('GET', `${url}?userId=${JSON.parse(res).userId}`))
  .then(JSON.parse)
  .then(render)
  .catch(console.error);
  ```

## Async / Await
Promise를 동기 코드처럼 위에서 아래로 읽히게 쓰는 문법이다. 
```js
async function 함수명() {
  await 비동기_처리_메서드_명();
}
```
- `async`: "이 함수 안에서 기다리는 일이 있다"는 표시.
- `await`: Promise가 끝날 때까지 이 함수 안에서만 기다린다. 성공하면 결과값을 돌려주고, 실패하면 에러를 던진다.
- `try / catch`: await에서 던진 에러를 잡는다. `.catch()` 역할이다.
`response.ok`: fetch는 404나 500이 와도 실패로 치지 않는다. 그래서 상태 코드(Part 1의 그것)를 직접 확인해서 에러를 던져야 한다.
```js
async function fetchProducts() {
  try {
    const response = await fetch(url);
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    const data = await response.json();
    console.log(data[0].name);
  } catch (error) {
    console.error(`Could not get products: ${error}`);
  }
}
```

# GDG 프론트엔트 스터디 영상 정리

## 서버
컴퓨터의 서버  
'서빙하는 사람 정도'  
고객(클라이언트)이 요청을 하면 서빙을 함  

- 요청: 서버한테, Todo 데이터를 보내달라고 함  
- 응답: 클라이언트한테 Todo데이터를 보내줌

API: 클라이언트와 서버 간에 데이터를 주고 받는 통로 역할  

프론트엔드: 맨 앞, 사용자가 직접 상호작용하는 웹 페이지의 화면을 다루는 개발 영역  
백엔드: 맨 위, 서버에서 동작하는 부분을 다루는 개발 영역  

### fetch 함수
네트워크 요청을 서버 데이터로 받아오는 Js 표준 함수  
fetch 함수는 비동기로 처리한다. 

루프:  
1. API 데이터 가져와
2. API 데이터를 state에 넣어
3. state 바뀌면 업데이트 해
4. 컴포넌트의 코드를 다시 시작해

React 컴포넌트는 순수한 함수라서 input이 같아면 output이 칻아야 한다.  

Hook: 외부의 영향을 알 수 있도록 걸어주는 갈고리

### useEffect Hook
외부의 효과를 렌더링과 분리하기 위해 존재한다.  
외부 효과는 DOM 조작에 직접적으로 관여하지 않는다.  

useEffect는 의존성 배열이라는 인자가 존재한다.
