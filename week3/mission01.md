# HTTP와 API
## HTTP
웹 브라우저(또는 프로그램)와 서버가 서로 대화할 때 쓰는 약속
HyperText Transfer Protocol
requests : 클라이언트에 의해 전송되는 메시지
responses : 서버에서 응답으로 전송되는 메시지
클라이언트 : 사용자를 대신하여 동작하는 모든 도구
## API
클라이언트와 서버 간의 데이터를 주고 받는 통로 역할
서로 다른 소프트웨어인 두 역할간 상호작용을 돕는 인터페이스
-----------------
# 동기
- 직렬적으로 태스크를 수행하는 방식
- 요청을 보낸 후 응답을 받아야지만 다음 동작이 이루어지는 방식
- 시스템의 전체적인 효율이 저하 
-----------------
# 비동기
- 코드가 끝날때 까지 코드의 실행을 멈추지 않고 다음 코드를 먼저 실행
- 병렬적
- 자원을 효율적으로 사용 가능
## 콜백함수
다른 함수의 인자(매개변수)로 전달되어, 특정 작업이 끝난 후나 어떤 이벤트가 발생했을 때 호출되는 함수
---------------------
# Promise
- 전통적인 콜백 패턴이 가진 단점을 보완하며 비동기 처리 시점을 명확하게 표현
### promise의 상태 정보
- pending: 비동기 처리가 아직 수행되지 않은 상태
- fulfilled: 비동기 처리가 수행된 상태 (성공)
- rejected: 비동기 처리가 수행된 상태 (실패)
- settled: 비동기 처리가 수행된 상태 (성공 또는 실패)
-------------------------
# async / await
함수와 프로미스의 단점을 보완
## async
- async를 붙이면 해당 함수는 항상 프라미스를 반환
- 프라미스가 아닌 것은 프라미스로 감싸 반환
## await
- 프라미스가 처리될 때 까지 기다리는 역할
- cpu 리소스 낭비 x
